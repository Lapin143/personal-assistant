# Ассистент

Семейное приложение: финансы, цели, вишлист, напоминания, авто, дом, документы, здоровье, люди.
Работает как статический сайт (без сервера). Тестовая версия.

## Как открыть

Settings → Pages → Source: Deploy from a branch → `main`, папка `/ (root)`.
Адрес: https://lapin143.github.io/personal-assistant/

## Данные

- Данные хранятся в браузере (localStorage). Стартовый шаблон — `data.json`.
- Перенос между устройствами: Люди → Данные → Экспорт / Импорт.
- **Важно:** репозиторий публичный. Для теста данные в `data.json` не важны, но не коммитьте
  туда реальные финансы. Безопасное хранение решим отдельно.

## Напоминания

Вверху любого раздела показывается блок «Скоро» с событиями в пределах
«Дней заранее» (настройка в разделе «Люди»). Скрыть до завтра можно кнопкой ✕.

## Разделение прав

Выбор «Кто вы» скрывает личные операции других участников. Это только удобство интерфейса:
все данные лежат в браузере и в файле. Настоящая защита будет отдельной задачей.

## Файлы

- `core.js` — расчёты (ближайшие события, сводка месяца, расход топлива, цели, долги). Без DOM.
- `app.js` — интерфейс.
- `index.html`, `style.css` — разметка и стили.
- `data.json` — стартовые данные.

## Меню: неделя, покупки, статистика

- **Неделя** — календарная неделя (пн–вс). Завтрак обязателен, обед можно отключить на любой день, ужин по желанию. Супы считаются обедом и готовятся на два дня.
- **Покупки** — после подтверждения меню граммовки суммируются (меньшая + большая порция) и группируются по категориям. Отметки видны всем, кто открывает приложение.
- **Закупка** — итог вводится вручную или загружается чек (PDF с текстом, CSV, TXT). Операция появляется в «Финансах».
- **Статистика** — расходы на продукты по месяцам: кольцевая диаграмма по категориям, столбцы по неделям, самые дорогие позиции.
- **Блюда** — библиотека с граммовками. Для каждого продукта задаются количества для меньшей и большей порции.

### Синхронизация через Supabase (по желанию)

Без настройки данные хранятся только на устройстве. Чтобы партнёр видел тот же список:

1. Создайте проект на supabase.com.
2. В SQL Editor выполните:
   ```sql
   create table family_data (
     id text primary key,
     payload jsonb not null,
     updated_at bigint not null
   );
   alter table family_data enable row level security;
   create policy "family anon access" on family_data for all to anon using (true) with check (true);
   ```
3. Впишите `url` проекта и публичный `anon`-ключ в `config.js`.

> Внимание: эта схема без входа в аккаунт. Любой, кто знает URL и ключ, может читать и менять данные. Ключ попадает в публичный код GitHub Pages. Для приватных данных нужна авторизация (Supabase Auth) и более строгие политики. Это следующий шаг.

## Вход и доступ (Supabase Auth)

Приложение открывается только после входа по email и паролю. Регистрация закрыта.

Настройка в панели Supabase (один раз):
1. **Authentication → Sign In / Providers → Email**: выключите «Allow new users to sign up».
2. **Authentication → Users → Add user**: создайте два аккаунта (владелец и супруга), задайте пароли и отметьте «Auto Confirm User».
3. **SQL Editor** выполните (заменит анонимную политику):

   ```sql
   drop policy "family anon access" on family_data;
   create policy "family members only" on family_data
     for all to authenticated using (true) with check (true);
   ```

Вход сохраняется на устройстве. Кнопка «Выйти» в Настройках удаляет данные с этого устройства, в облаке они остаются.
