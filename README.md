# Ассистент

Семейное приложение: финансы, меню и покупки, цели, напоминания, авто, списки.
Статический сайт (без своего сервера), устанавливается на телефон как PWA.

Адрес: https://lapin143.github.io/personal-assistant/

## Разделы

- **Главная** — доходы и расходы за месяц с прогнозом на конец месяца, меню на сегодня, ближайшие 14 дней, цели.
- **Меню** — план на месяц вперёд: блюда по приёмам пищи, отметка «едим дома», автозаполнение пустых дней, подтверждение месяца, списки покупок, статистика, библиотека блюд.
- **Финансы** — операции, регулярные платежи (проводятся после подтверждения), поступления (зарплата и т. п.), долги, бюджет по категориям, итоги за год, отчёт с кнопкой «Отправить».
- **Цели** — долгосрочные и краткосрочные цели, подушка безопасности, вишлист.
- **Напоминания** — календарь месяца с категориями. Категории настраиваются в Настройках: можно включать, выключать, переименовывать и добавлять свои. Дни рождения — категория «День рождения» с повтором «каждый год».
- **Авто** — автомобили, расходы, сроки страховки и техосмотра, расход топлива.
- **Списки** — любые списки с отметками. Список и пункты можно переименовывать и править.
- **Настройки** — участники и вход, счета и категории расходов и доходов, напоминания, тема, резервная копия.

## Меню: как устроено

- Месяц делится на календарные недели (пн–вс). Завтрак обязателен, обед и ужин можно отключить на любой день галочкой «едим дома».
- Супы считаются обедом и готовятся на два дня.
- Граммовки суммируются по меньшей и большей порции. Штучные овощи и фрукты округляются на каждый приём отдельно: половинку помидора не оставляют на завтра.
- После подтверждения месяца формируются:
  - один список долгохранимых продуктов (крупы, бакалея) — покупается раз в месяц;
  - недельные списки со статусом «закуплено» после покупки.
- Чек можно загрузить как PDF с текстом, CSV, TXT или фото (распознавание текста идёт на устройстве и может ошибаться). Покупка появляется в «Финансах».

## Данные и вход

- Данные хранятся в браузере (`localStorage`) и синхронизируются между устройствами через облако: приложение → функция в Yandex Cloud → база в Табрике.
- Браузер не обращается к Табрике напрямую. Токен Табрики, ID базы и таблицы, пароли участников лежат только в переменных окружения функции. В репозитории и в коде сайта секретов нет.
- Вход по логину и паролю. Пароль проверяет функция и выдаёт подписанный пропуск на 90 дней; он хранится на устройстве. Смена пароля участника отзывает его пропуска, смена `AUTH_SECRET` — пропуска всех.
- Кнопка «Выйти» в Настройках удаляет локальные данные с устройства; в облаке они остаются.
- Резервная копия: в Настройках → Данные, файл `assistant-data.json`. Файл содержит финансы, не публикуйте его.

### Когда приложение обращается к серверу

Фоновых опросов по таймеру нет. Запросы идут только в трёх случаях:

1. При открытии приложения (и при возврате в него после паузы): один запрос «что изменилось с прошлого раза».
2. После ваших изменений: через 6 секунд тишины все правки уходят одним пакетом, по одному запросу на изменённую запись.
3. По кнопке синхронизации в шапке (не чаще раза в 30 секунд) и по кнопке «Полная сверка» в Настройках.

Без связи приложение работает из данных на устройстве; изменения уходят, когда связь появится. Жёлтая точка на кнопке синхронизации означает, что есть неотправленные изменения.

### Как данные лежат в Табрике

Одна таблица `records`, одна строка на сущность:

| kind | key | Что это |
|---|---|---|
| `tx` | id операции | Одна операция финансов. Поля `date`, `amount`, `category` заполнены, чтобы таблицу было удобно смотреть в Табрике |
| `menu` | `ГГГГ-ММ` | Меню месяца целиком: недели, статус, покупки |
| `list` | id списка | Один список со всеми пунктами |
| `settings` | `main` | Общие настройки, люди, счета, категории |
| `doc` | имя раздела | Остальные разделы: цели, напоминания, авто, регулярные платежи и т. д. `history_json` — итоги закрытых месяцев |

Служебные поля: `updated` (время изменения, ставит функция), `deleted` (пометка об удалении), `title` (подпись для чтения глазами), `data` (JSON с содержимым).
JSON длиннее 20 000 символов (например, библиотека блюд) делится на несколько строк с ключами `имя#1`, `имя#2`: Табрика не принимает внутри JSON строку длиннее 50 000 символов. Не правьте строки приложения в Табрике вручную: оно считает их содержимое своим. Строку, удалённую в Табрике, приложение при полной сверке уберёт и с устройств; если очистить таблицу целиком, данные вернутся с первого устройства, которое синхронизируется. Свои строки с другим значением `kind` приложение не трогает.

### Лимиты бесплатных тарифов

- **Табрика: 1 000 строк, 3 000 запросов в месяц.** Обычное использование двумя людьми (8 открытий и 6 изменений в день у каждого) — около 800 запросов в месяц. Счётчик запросов устройства виден в Настройках → Синхронизация; общий — в Табрике: Настройки → Статистика. После 1 200 запросов с одного устройства за месяц оно переходит в экономный режим: автообновление при открытии не чаще раза в час.
- **Yandex Cloud Functions: 1 000 000 вызовов в месяц.** Приложение делает один вызов функции на синхронизацию, то есть меньше 1 % лимита.

### Закрытие месяца

В «Финансах» у прошедшего месяца есть кнопка «Закрыть месяц». Она освобождает строки в Табрике:

1. Скачивается файл-копия `assistant-ГГГГ-ММ.json` с операциями месяца.
2. Итоги (доход, расход, суммы по категориям) записываются в `history_json`.
3. Только после этого операции месяца удаляются из таблицы и с устройств.

Графики, бюджет и вкладка «Год» продолжают показывать суммы закрытого месяца. Отдельные операции вернуть нельзя (только посмотреть в файле-копии). Операция, добавленная в уже закрытый месяц, сразу попадает в его итоги.

## Развёртывание серверной части (один раз)

### 1. Табрика

1. В базе создайте таблицу `records` с полями: `key` (текст), `kind` (текст), `updated` (число), `date` (текст), `amount` (число), `category` (текст), `title` (текст), `data` (JSON), `deleted` (число).
2. ID базы и ID таблицы видны в адресе открытой таблицы: `…/db/<ID базы>/table/<ID таблицы>`.
3. Настройки организации → вкладка **API** → создайте токен с правами «чтение и запись». Токен показывается один раз.

### 2. Yandex Cloud Function

1. Cloud Functions → функция → вкладка **Редактор**, среда выполнения **Node.js 22**.
2. Вставьте в `index.js` содержимое файла [`cloud/index.js`](cloud/index.js). Точка входа: `index.handler`. Таймаут: 60 секунд, память 128 МБ.
3. Задайте переменные окружения:

   | Переменная | Значение |
   |---|---|
   | `TABRICA_TOKEN` | токен из Табрики (секрет) |
   | `TABRICA_DB_ID` | ID базы |
   | `TABRICA_TABLE_ID_RECORDS` | ID таблицы `records` |
   | `AUTH_SECRET` | любая случайная строка от 32 символов (секрет) |
   | `AUTH_USER_1` | `логин:пароль` первого участника, пароль от 8 символов (секрет) |
   | `AUTH_USER_2` | `логин:пароль` второго участника (секрет) |
   | `ALLOWED_ORIGINS` | адрес сайта, например `https://lapin143.github.io` |

4. Нажмите **Сохранить изменения**: соберётся новая версия функции.
5. На вкладке **Обзор** включите **Публичная функция**: иначе сайт не сможет её вызвать. Защищает функцию не закрытость адреса, а вход по паролю.
6. Впишите ссылку для вызова функции в `config.js`.

Чтобы сменить пароль или добавить участника (`AUTH_USER_3` и т. д.), измените переменные и сохраните новую версию. Секреты в `config.js` и в репозиторий не добавляйте.

### 3. Проверка без облака

```bash
node cloud/test.mjs        # функция: вход, пропуска, CORS, маршрутизация
node cloud/sync.test.mjs   # синхронизация двух устройств через код функции и имитацию Табрики
node cloud/dev-server.mjs  # локальный стенд на http://localhost:8080 с тестовыми логинами
```

## Файлы

- `index.html`, `style.css`, `features.css`, `menu/planner.css` — разметка и стили.
- `app.js` — интерфейс: разделы, формы, навигация, вход.
- `features.js` — бюджет, прогноз, подушка, поступления, календарь, списки, чеки, голосовой ввод.
- `menu/planner.js` — месячное меню, покупки, статистика, библиотека блюд.
- `core.js` — расчёты без DOM: ближайшие события, сводка месяца, топливо, цели, долги.
- `api.js` — вход и запросы к функции-прокси.
- `store.js` — разбор данных на записи и синхронизация (без DOM, покрыт тестами).
- `config.js` — адрес функции и имя таблицы. Секретов нет.
- `cloud/index.js` — код функции Yandex Cloud; `cloud/*.mjs` — тесты и локальный стенд.
- `data.json` — стартовые данные (люди, счета, категории, библиотека блюд).
- `sw.js`, `manifest.webmanifest`, `icon.svg` — офлайн-режим и установка на экран телефона.

Версии файлов указаны в `?v=…` в `index.html` и в импортах. При каждом изменении поднимайте версию и номер кэша в `sw.js` (`CACHE`), иначе браузер покажет старую копию.

## Разделение видимости

Выбор «Кто вы» скрывает личные операции других участников. Это удобство интерфейса: данные доступны каждому, кто вошёл в приложение.
